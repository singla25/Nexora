# Security matrix

Every way into the Nexora plugin, with who may use it and what protects it. **`tests/php/test-security-matrix.php` fails if an entry point exists that is not in a row below (or a row names one that is gone)**, so a new AJAX action, admin-post action, row action, shortcode, REST route, WP-Cron event or request hook cannot ship without a row. Each row must answer all seven questions; the rate-limit buckets named here must exist in `Http\Rate_Limiter::defaults()` and every bucket must be named by a row.

How to read it: *Nonce* is the WordPress nonce action checked; *Permission* is the capability or ownership rule; *Guest* says whether a logged-out visitor may call it (`wp_ajax_nopriv_` or `admin_post_nopriv_`); *Input* is what is validated; *Output* is how the answer is escaped.

Common guards (named in the rows):

- **Member guard** (`Http\Ajax::member()` / `Http\Member_Ajax`): nonce `profile_nonce`, logged in, `read`, and a profile post for the caller. The profile comes from the logged-in user, never from the request.
- **Seller guard** (`Vendors\Vendor_Ajax::seller()`): the member guard plus `Account_Types::can_sell()` (approved status AND the seller role). **Earnings viewer**: approved or suspended (a suspended seller reads history, nothing more). The seller record always comes from the logged-in user.
- **Admin Gate** (`Core\Admin_Gate`): the only way an administrator gets past `Core\Post_Guard`: `manage_options`, the wp-admin post screen (never AJAX, REST or cron), the right method, and the nonce of that exact post and action.
- **Rate limits** (`Http\Rate_Limiter`): buckets are counted per IP for guests and per member for members; a limit answers with a plain message and never blocks an order.
- **Output**: JSON answers carry text, never markup built from user data; HTML comes from templates (`Core\View`), which escape every value (`esc_html`, `esc_attr`, `esc_url`, `esc_textarea`).

The deprecated un-prefixed AJAX names (for example `wp_ajax_sales` as well as `wp_ajax_nexora_sales`) call the same handler through `Http\Ajax::register()`, so they have the same guard; one row covers them all. The chat actions and the document download never had an un-prefixed name.
